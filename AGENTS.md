# Работа с репозиторием

## Правила проекта

Перед написанием, изменением и ревью Go-кода прочитай:

- [.agents/rules/coding.md](.agents/rules/coding.md) — принципы понятного кода, выделения обязанностей и работы с данными.
- [.agents/rules/architecture.md](.agents/rules/architecture.md) — размещение команд и пакетов, ответственность точек входа и границы тестирования.
- [.agents/rules/testing.md](.agents/rules/testing.md) - принципы написания тестов и работы с ними.

Оформление и автоматические проверки определяет [.golangci.yml](.golangci.yml).
Версии Go, инструментов и зависимостей бери из `go.mod`. Инструменты запускай через `go tool` и цели Makefile.

## Порядок работы

Перед правкой изучи затрагиваемый код, его вызовы и существующие решения похожих задач.
Определи, какое поведение требуется изменить и какие гарантии нужно сохранить.
Применяй правила проекта к конкретной задаче; выбирай решение, которое понятно в её контексте.

## Команды

Выполняй команды из корня репозитория.

| Задача | Команда |
| --- | --- |
| Применить форматирование | `make fmt` |
| Проверить конфигурацию линтера и код | `make lint` |
| Собрать исполняемые программы | `go build ./cmd/...` |
| Запустить все тесты | `go test ./...` |
| Запустить сервис | `go run ./cmd/service` |

Для проверки конкретного пакета передай его путь в `go test`.
Необходимые настройки окружения и внешние сервисы уточняй по документации и конфигурации репозитория.

## Перед завершением

После изменения Go-кода выполни `make fmt`, `make lint` и проверки затронутого поведения.
При изменении точек входа или сборки дополнительно выполни `go build ./cmd/...`.
Выбирай тесты по требованиям задачи и правилам архитектуры.
Просмотри итоговый diff и проверь, что изменения соответствуют задаче.

В результате кратко сообщи, что изменено, какие проверки выполнены и что осталось непроверенным.

## Миграции

Пиши миграции только вперёд. Не добавляй секции `Down` и SQL для отката изменений.
